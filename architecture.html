Smart PDF Tutor Architecture

This document explains the structure of the project, the main components, and how they interact to turn uploaded PDFs into an AI-powered learning experience.

1. Project Overview

The Smart PDF Tutor is a full-stack application that allows users to upload PDF files and interact with them using AI-powered features such as question answering, summarization, quizzes, and flashcards.

The system is divided into three major layers:

  • Frontend – user interface for uploading PDFs and chatting with the tutor.
  • Backend – API layer that processes uploads, extracts text, and prepares data for AI features.
  • Data and AI Services – PDF parsing, chunking, embeddings, and LLM integration.

2. High-Level Architecture

Flow:
User uploads PDF → Backend stores file → PDF text is extracted → Text is split into chunks → Chunks are prepared for embeddings/LLM → AI responses are returned to the frontend.

3. Main Components

3.1 Frontend Components

App

The root React application that wires the pages and routes together.

Home Page

Provides the main landing experience, including the PDF upload interface and feature overview.

Chat Page

Lets the user ask questions about the uploaded document and displays AI replies.

PDFUpload Component

Handles file selection, validation, and sending the file to the backend.

Navigation Component

Provides basic page navigation across the app.

3.2 Backend Components

FastAPI App

The main server application that defines routes and handles incoming requests.

Upload Endpoint

Receives a PDF file, stores it locally, and extracts text from it.

Question Endpoint

Accepts a user question and returns an answer based on the document context.

Summarize Endpoint

Planned endpoint for generating summaries from uploaded content.

Quiz Endpoint

Planned endpoint for generating quiz questions from the document.

3.3 Service Components

PDFProcessor

Responsible for reading PDFs, extracting text, returning page content, and splitting text into chunks.

EmbeddingsService

Prepares text for semantic search and similarity matching. This is used for future retrieval-based AI features.

LLMService

Will connect the app to an LLM such as OpenAI or Gemini to generate grounded answers and study features.

4. Data Flow

  1. User selects and uploads a PDF from the React frontend.
  2. The backend accepts the file through the upload endpoint.
  3. The PDF is read and text is extracted by the PDF processor.
  4. The text is divided into smaller chunks for later processing.
  5. The system can then use embeddings and an LLM to answer questions or generate study help.
  6. The final response is sent back to the frontend and displayed in the chat interface.

5. Current Project Status

  • Implemented: React frontend, FastAPI backend, PDF upload, PDF extraction, basic tests.
  • Planned: embeddings, vector search, RAG pipeline, LLM integration, authentication, and database persistence.

6. Suggested Future Architecture

As the project grows, the architecture can evolve into:

  • Database layer for users, documents, and chat history
  • Vector database such as FAISS or Chroma for document retrieval
  • Authentication service for user accounts
  • Deployment layer with frontend on Vercel and backend on Render or Railway
